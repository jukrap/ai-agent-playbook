# Codex 모델 사용과 기록 초안

이 문서는 AAPB 지침을 지원되는 Codex 호스트에 맞춰 사용할 때 선택적으로 읽는 참고 자료입니다. AAPB는 사용자의 모델, 추론 강도, 수치 설정, 권한과 서비스 설정을 보존합니다. [개인 템플릿](../../templates/codex-home/README.ko.md)과 [프로젝트 지침](../../templates/agents/README.ko.md)은 공통 작업 규칙을 제공하며 모델을 선택하지 않습니다.

## 주 작업

조사, 설계, 구현, 검증과 검토는 사용자가 선택한 Astra 또는 Sol로 진행합니다. Sol도 주 작업 모델입니다. 사용자가 Sol `xhigh`나 `max`를 선택했다면 비용이 절감될 것이라는 추측으로 강도를 낮추거나 Astra로 되돌리지 않습니다. 선택적인 기록 담당 에이전트를 고르는 일과 주 작업 모델을 바꾸는 일은 별개입니다.

허용된 작업을 완료하고 명시적 승인을 지킵니다. 현재 코드와 의도한 계약을 구분하고 좁게 탐색한 뒤 필요하면 넓히며, 변경된 동작과 필수 검사를 확인합니다. 스킬 수를 고정하거나 전체 이력 읽기를 요구하지 않고 관련 지침과 근거를 읽습니다. 이는 AAPB의 작업 정책입니다. [공식 모델 가이드](https://developers.openai.com/api/docs/guides/latest-model)는 모델별 참고 자료이며 프로젝트 규칙이나 설정을 다시 쓰라는 요구가 아닙니다.

## 선택적인 Sol 초안

기록은 보통 메인 작업에서 직접 작성합니다. 길고 독립적인 작업 일지, 지식 문서나 인계 초안 작성이 도움이 되고 호스트가 지원한다면 Sol에 맡길 수 있습니다. 메인이 이미 Sol이면 같은 일을 다시 위임할 필요는 없습니다. 요청한 역할이나 모델이 없으면 메인 작업에서 계속합니다. AAPB는 모델 실행기나 자동 예약기를 제공하지 않습니다.

초안 담당자에게 범위를 정한 근거 묶음과 짧은 관련 이력을 전달합니다. 산출물과 독자, 저장 위치, 등록된 저장소 ID, 허용 범위와 로컬 전용 제약, 채택한 결정, 정확한 소스 경로와 범위, 수치와 단위, 명령과 관측 결과, URL, 날짜, 가정, 미확인 사항, 생략한 검사와 남은 일을 포함합니다. 해당 업무에 필요한 소스 파일만 전달하세요.

응답이나 별도 담당 파일에 DRAFT임을 분명히 표시한 초안을 요청합니다. 공통 CURRENT.md와 채택한 지식 문서는 담당자를 하나씩 유지합니다. 메인은 반영 전에 출처 경로와 범위, 수치, 명령, URL, 결정과 미확인·미검증 상태를 원래 근거와 대조합니다. 해결하지 못한 불일치는 명시적으로 남깁니다. 필요할 때 상세 [근거와 인수인계 참고 문서](../../skills/project/project-memory/references/evidence-and-handoff.ko.md)를 사용하세요. 초안이 완성됐다는 사실만으로 내용의 정확성이 확인되지는 않습니다.

## 호스트 기능과 역할 설정

명시적인 역할별 모델과 추론 강도 설정을 보존합니다. 역할별 선택이 없으면 지원되는 범위에서 현재 작업의 추론 강도를 유지합니다. 기록 업무라는 이름만으로 강도를 낮추지 않습니다. 정확한 호출 형식은 실제 도구 스키마와 제공되는 모델을 확인해 정하세요. Codex 버전과 모델 기능에 따라 노출되는 spawn 필드가 달라질 수 있으므로 `agent_type`, `model`, `reasoning_effort`를 어디서나 쓸 수 있는 인자로 가정하지 않습니다. 존재하지 않는 에이전트 유형을 만들거나 지원되지 않는 필드를 강제로 전달하지 않습니다. [버전을 고정한 도구 정의](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/tools/handlers/multi_agents_spec.rs)를 참고하세요.

역할 프롬프트는 업무를 정하며 보안 샌드박스가 아닙니다. 격리가 중요하면 실제 호스트 권한과 작업 공간 접근 범위를 확인합니다. AAPB 문서가 이러한 권한을 바꾸지는 않습니다. 호스트 설정은 [공식 서브에이전트 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)에서 따로 설명합니다.

## 지원되는 호스트의 대기 동작

아래 비교는 승인된 조사의 기준인 Codex `rust-v0.153.4`를 설명합니다. 소스 근거이며, 모든 설치 호스트에서 기능을 사용할 수 있거나 호출에 성공했다는 증거는 아닙니다. 어느 방식을 사용하든 먼저 실제 도구 스키마를 확인하세요.

| 방식 | 대기 계약 | 시간 제한 처리 |
| --- | --- | --- |
| v1 `multi_agent_v1.wait_agent` | 에이전트 `targets`와 선택적 `timeout_ms`를 받습니다. 최종 상태를 반환하며 시간 초과 시 상태가 비어 있습니다. | 구현의 기본값과 범위를 사용하고 양수 요청값을 해당 범위로 제한합니다. [v1 처리 코드](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/tools/handlers/multi_agents/wait.rs)를 참고하세요. |
| v2 `wait_agent` | 대상 목록 없이 선택적 `timeout_ms`를 받습니다. 최종 상태 알림을 포함한 메시지 수신이나 현재 작업에 전달된 새 사용자 입력을 기다립니다. 대기가 끝났다고 해서 모든 에이전트가 완료된 것은 아닙니다. | `multi_agent_v2.min_wait_timeout_ms`, `multi_agent_v2.max_wait_timeout_ms`, `multi_agent_v2.default_wait_timeout_ms`를 읽습니다. 너무 작은 요청값은 최솟값으로 올리고 최댓값을 넘으면 거부합니다. [v2 처리 코드](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/tools/handlers/multi_agents_v2/wait.rs#L53)를 참고하세요. |

이 v2 설정은 해당 대기 동작에만 적용되며 v1, 셸 대기, 다른 도구나 에이전트 전체 실행 시간을 바꾸지 않습니다. 각 계약이 지원하는 활동이 발생하면 일찍 반환할 수 있습니다. AAPB는 25분 프리셋을 설치하거나 사용자의 기존 값을 다시 쓰지 않습니다. 독립적으로 할 수 있는 일을 계속하고, 기다려야 한다면 호스트의 소통 요건에 맞는 제한된 대기를 사용하며 변하지 않은 상태를 계속 조회하지 않습니다. 시간 초과만으로 작업이 실패했다고 판단하거나 실행 중인 담당자를 포기하지 않습니다.

## API 기능과 검증 주장

프롬프트 캐시, 비동기 API 호출과 `configuration_update`는 API 클라이언트나 호스트의 지원이 필요하며 AAPB 설정이 아닙니다. [공식 추론 안내](https://developers.openai.com/api/docs/guides/reasoning#change-reasoning-mid-conversation)는 설정 갱신을 지원되는 Astra 단일 에이전트 요청으로 제한하며 자동 압축·자동 잘라내기와의 병용을 허용하지 않습니다. API 예제를 Codex 설정 항목으로 바꾸어 설명하거나 이를 통해 사용자의 추론 강도 선택을 변경하지 않습니다.

설정, 로딩, 호출과 실제 동작 검증을 구분해 보고합니다. 기록 작성 방식을 비교할 때는 같은 근거 묶음과 완료 조건을 사용하고 실제 모델·추론 강도, 누락, 왜곡, 검토 중 수정, 호출, 경과 시간과 확인 가능한 사용량을 기록합니다. 사용량을 확인할 수 없으면 unknown으로 남기고 API 가격으로 구독 한도 절감률을 추정하지 않습니다. 관련 입력과 조건이 같고 필수 검사 규칙이 허용할 때만 결과를 재사용합니다.
