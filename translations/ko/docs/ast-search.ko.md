# 코드 구조 검색

줄바꿈이나 공백이 달라도 같은 형태의 함수 호출을 찾거나 특정 JSX 표현을 찾을 때 AST 검색을 사용합니다. 프로젝트 기록의 문자열 검색은 `records search`, 소스의 구조 검색은 `ast search`입니다. 예전의 전체 심층 분석·언어 서비스·인덱스·코드 교체 기능은 복구하지 않고 구조 검색만 제공합니다. 설치되는 스킬 수는 늘어나지 않습니다.

## 프로젝트에서 검색하기

```powershell
ai-agent-playbook ast search --lang javascript --pattern 'console.log($$$ARGS)' --path src --json
ai-agent-playbook ast search --lang tsx --pattern 'useState($VALUE)' --path src --max-results 10 --json
```

프로젝트 경로를 생략하면 현재 터미널의 작업 폴더를 사용합니다. 위치 인자나 `--project`로 다른 루트를 지정할 수도 있습니다. `--path`는 프로젝트 안의 파일 또는 폴더이며, 생략하면 선택한 프로젝트를 검색합니다. PowerShell과 POSIX 셸에서는 패턴을 작은따옴표로 감싸야 `$VALUE`, `$$$ARGS`가 그대로 전달됩니다. 큰따옴표를 쓰면 셸이 패턴을 바꿀 수 있습니다.

| 인자 | 의미 |
| --- | --- |
| `--pattern` | 필수 ast-grep 구조 패턴. 최대 4096자 |
| `--lang` | 필수 언어. `javascript`, `typescript`, `tsx`, `jsx`, `css`, `html` 중 선택하며 해당 확장자의 파일만 검색 |
| `--path` | 상대 파일·폴더 경로. 와일드카드와 상위 경로 이동은 허용하지 않음 |
| `--max-results` | 한 페이지의 결과 수. 기본 20개, 최대 100개 |
| `--max-chars` | 페이지 내용 예산. 기본 12000자, 최대 100000자이며 전체 작업의 토큰 제한은 아님 |
| `--max-files` | 한 번에 파싱할 파일 수. 기본 1000개, 최대 4000개 |
| `--cursor` | 같은 프로젝트·경로·언어·패턴·파일 제한으로 다음 결과 페이지 조회 |
| `--json` | 검색 범위와 이어 읽기 정보를 포함한 구조화된 출력 |

결과에는 프로젝트 상대 경로, 1부터 시작하는 줄과 UTF-16 기준 열, 일치 구간 바로 뒤의 종료 위치, 최대 500자의 코드 조각이 있습니다. 코드 조각이 줄어들면 `snippetTruncated`가 표시됩니다. 전체 내용은 소스의 해당 구간에서 확인하세요. `page.nextCursor`로 다음 페이지를 읽습니다. 검사한 소스 내용이나 검색 범위가 달라지면 커서를 거부합니다. 이어 읽기도 입력을 재검증하기 위해 제한된 범위를 다시 검색하므로 경로를 좁히면 반복 작업을 줄일 수 있습니다.

## 결론을 내리기 전에 검색 범위 확인하기

Git 저장소에서는 `git ls-files`로 추적 파일과 무시되지 않은 미추적 파일을 선택합니다. 추적 중인 파일은 나중에 추가한 ignore 규칙과 일치해도 포함됩니다. Git을 사용할 수 없으면 정해진 제외 폴더를 적용해 파일시스템을 탐색하며 `.gitignore`를 해석하지 않습니다. `scan.sourceMode`로 두 방식을 구분합니다.

생성물·의존성·로컬 기록 폴더는 항상 제외합니다. `.git`, `node_modules`, `dist`, `build`, `coverage`, `.next`, `.turbo`, `.venv`, `.ai-agent-playbook`, 구형 숨김·일반 플레이북 폴더, `.refra-scope`, `_reference`, `_work`가 해당합니다. 링크된 파일·폴더와 Windows junction을 따라가지 않으며, 이를 경로로 직접 지정해도 거부합니다.

파일당 1 MB, 전체 소스 32 MB, 디렉터리·목록 항목 20000개, 수집 결과 5000개, 검색 worker 실행 시간 30초가 상한입니다. 상한 도달, 읽을 수 없거나 너무 큰 파일, 바이너리, 관찰된 파서 오류는 결과에 표시됩니다. `scan.complete`와 경고 표본을 확인하세요. 결과 페이지를 끝까지 읽었다고 소스 전체를 검색한 것은 아닐 수 있습니다. 불완전한 검색에서 결과가 0개라는 이유로 해당 코드가 없다고 판단하면 안 됩니다.

검색은 읽기 전용입니다. 프로젝트 코드, ast-grep 설정, 사용자 문법과 셸 명령을 실행하지 않습니다. worker는 소스 텍스트를 파싱하며 Git은 파일 선택에만 사용합니다. 파서 실패를 정규식 검색 결과로 대신하지 않습니다. Tree-sitter의 구조 일치는 타입·의미의 동일성이나 컴파일·실행 성공을 보장하지 않습니다.

## 선택 의존성과 MCP 노출

npm 패키지는 `@ast-grep/napi`를 선택 의존성으로 선언합니다. 일반 설치에서는 지원 플랫폼의 네이티브 모듈도 설치하며, `--omit=optional`로 제외할 수 있습니다. 디스크 설치 용량은 늘지만 파서는 AST 호출 때만 로딩합니다. 모듈이 없거나 실행할 수 없으면 `aapb.ast-engine-unavailable`을 반환하고, 기존 기록 명령과 기본 MCP는 계속 사용할 수 있습니다. 제외한 엔진을 복구하려면 사용할 패키지 버전을 `--include=optional`로 다시 설치하세요. 검색 호출이 엔진을 자동 다운로드하지는 않습니다.

기본 MCP는 기존 기록 도구 네 개를 유지합니다. 읽기 전용 `aapb_ast_search`를 추가하려면 서버를 한 번 다음과 같이 설정합니다.

```sh
ai-agent-playbook mcp --with-ast
```

새 도구는 서버가 연결된 프로젝트 안에서 `pattern`, `lang`, `path`, `maxFiles`, `maxResults`, `maxChars`, `cursor`를 받습니다. 다른 프로젝트를 선택하거나 일치한 코드를 수정할 수 없습니다. 기존과 같이 MCP 응답 전체에 256 KiB 상한을 적용합니다. 활성화하면 도구 정의도 노출됩니다. 선택형 등록이 컨텍스트 비용 0이나 호스트의 지연 로딩을 보장하지는 않습니다.

Codex에서 `npx`로 등록했다면 `mcp` 뒤에 `--with-ast`를 추가합니다. `enabled_tools`가 있다면 기존 기록 도구 네 개와 함께 `aapb_ast_search`도 넣으세요. 등록 변경 후 서버·세션을 다시 시작하면 매 작업마다 켤 필요는 없습니다. 이 기능이 포함된 패키지 버전을 사용해야 합니다. 저장소에서 구현했다고 이미 설치·실행 중인 npm 패키지까지 바뀌지는 않습니다.

예전 `ast_grep_search` MCP 이름, `operator analyze --deep`, AST 교체 명령, 언어 서비스 도구는 복원하지 않습니다. 새 구조 검색 계약을 사용하세요. 나머지 기능은 [에이전트 사용법](agent-usage.ko.md)과 [MCP 설정](mcp-permission-model.ko.md)에서 설명합니다.

## 확인한 범위

Windows의 Node.js 22.22.3에서 AST 회귀 15개를 포함한 전체 테스트 154개와 정적·타입·Python·문서 검사, 설치 미리보기가 통과했습니다. Node.js 18.20.8에서도 AST 15개와 기본 MCP 검사 1개가 통과했습니다. 이 과정에서 Windows junction 발견 방식의 차이를 확인하고, 링크 하나 때문에 폴더 검색 전체가 실패하는 대신 건너뛴 범위를 표시하도록 보완했습니다.

별도 npm 설치본으로 기존 TSX·TypeScript 프로젝트에 CLI와 실제 SDK stdio 호출을 수행했습니다. 두 통로의 검색 결과가 일치했고 프로젝트 파일은 그대로였습니다. 선택 의존성을 뺀 설치에서도 기본 MCP는 동작했고 AST만 명확한 엔진 누락 오류를 반환했습니다. 모든 호스트의 자동 도구 선택, 다른 플랫폼의 네이티브 호환성, 속도·토큰 개선을 입증한 검사는 아닙니다. 30초 응답 제한은 구현했지만 의도적으로 멈추지 않는 네이티브 파서 사례는 실행하지 않았습니다.

패턴·API 참고: [ast-grep JavaScript API](https://ast-grep.github.io/guide/api-usage/js-api.html).
