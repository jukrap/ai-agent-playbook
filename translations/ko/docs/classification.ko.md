# 콘텐츠를 어디에 둘까요?

재사용 지침, 프로젝트 파일, 실행 코드, 사람용 안내는 독자와 관리 방식이 다릅니다. AAPB는 이를 구분해서 배치합니다.

| 위치 | 내용 | 사용 방법 |
| --- | --- | --- |
| `skills/<category>/<name>/SKILL.md` | 짧은 사용 조건과 해당 제약 | 에이전트 앱이 찾아 필요한 스킬 선택 |
| 스킬 안의 `references/` | 해당 스킬에 필요한 상세 내용 | 스킬과 함께 설치, 필요할 때 읽기 |
| 루트 `references/` | 과거의 분야별 예시와 계약 | 직접 선택해서 참고. 별도의 스킬 목록이 아님 |
| `templates/agents/` | 복사 가능한 프로젝트 지침 | 기존 정책과 비교·검토해 적용 |
| `templates/project-playbook/` | 최소 현재 상태 템플릿과 관리 정보 | Bootstrap에서 사용, 상세 기록은 필요할 때 추가 |
| `examples/` | 완성 예시나 재사용 예시 | 형식과 의도를 참고. 현재 프로젝트 사실로 보지 않음 |
| `docs/`, README, CONTEXT | 시작 안내, 사용법, 구조, 유지보수 | 독자의 목적에 맞춰 탐색 |
| `adapters/` | 앱 설정과 연동 범위 | 사용하는 에이전트 앱에 맞춰 참고 |
| `src/`, `bin/` | 실행 가능한 CLI/MCP 동작 | 테스트하는 코드 |
| `translations/ko/` | 한국어 읽기용 문서 | 사람이 사용. 중복 스킬로 설치하지 않음 |

## 자료를 추가하거나 옮길 때

프로젝트에만 해당하는 사실은 재사용 스킬이 아니라 해당 프로젝트 기록에 둡니다. 산출물 형식은 형식 참고 자료에, 실행 시 지켜야 할 조건은 코드와 의미 있는 테스트에 둡니다. 초보자 실습은 길더라도 사람용 안내에 필요합니다. 연결된 스킬이 짧다는 이유로 줄이지 않습니다.

영문과 한국어는 기능 설명 범위를 함께 유지합니다. README의 브랜드, 언어 선택, 의도한 현지화 설명을 보존하세요. 런타임 지침을 줄인다는 이유로 사람용 탐색 구조와 예시를 없애지 않습니다.

구조를 바꾸기 전에 [유지보수 안내](maintenance.ko.md)를 읽습니다. 참고한 예시를 필수 지침으로 바꾸지 않고 보존하는 방법은 [참고 자료 활용](reference-adoption.ko.md)에 있습니다.
