# 개발·디자인·문서 환경

AAPB가 에이전트 앱의 모든 플러그인을 관리하지는 않습니다. 설치 도구는 소유권 표식이 있는 AAPB 스킬 디렉터리만 다룹니다. 플러그인 캐시, 계정 연결, 다른 프로젝트의 프로필은 별도로 확인해야 합니다.

## 원격 플러그인과 로딩

확인한 [호스트의 버전별 로더](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core-plugins/src/loader.rs)는 원격 계정의 활성 상태를 로컬 플러그인의 enabled 설정보다 우선 적용하고, 서버별 추가 설정은 보존합니다. 따라서 로컬 enabled=false만 편집해도 설치된 원격 플러그인이 비활성화되지 않을 수 있습니다.

계정 설치와 복구용 캐시를 보존하려면 지원되는 스킬 경로·이름별 선택 설정과 플러그인별 MCP의 enabled=false 설정으로 공통 노출을 제한합니다. 원격 플러그인을 로딩한 뒤 설치 상태와 스킬 목록을 다시 읽고, 새 턴의 실제로 대화에 들어간 목록과 MCP 런타임 상태를 확인합니다. 다음 항목을 구분합니다.

- 원격 계정의 설치·활성 상태
- 로컬 스킬·도구 노출
- 캐시 파일과 버전
- 발견 목록, 자동으로 대화에 들어간 지침과 실제 도구 호출

경로 선택자는 확인한 설치 버전에, 이름 선택자는 유지되는 진입점 이름에 적용됩니다. 플러그인이 새 이름이나 서버를 추가하면 다시 감사해야 합니다. 선택 플러그인이 의존성으로 선언했다고 공유 커넥터까지 비활성화하지 않습니다. 해당 권한과 복구 계획 없이 원격 플러그인 제거를 로컬 노출 제한의 대체 수단으로 사용하지 않습니다.

## 복구

적용 전 백업에서 바꾼 플러그인·스킬·MCP 설정만 복원합니다. 이전 뒤 현재 설정이 달라졌다면 관련 항목을 병합하고 새 모델·예산·데스크톱·프로젝트 설정을 보존합니다. 개인 설정을 이 저장소에 넣지 않습니다.

스킬 설치 작업과 플러그인 설정은 별개입니다. 스킬은 최신 작업부터 역순으로 복구하며, 각 복구를 미리 본 뒤 --apply로 적용합니다. 이전 CLI 패키지도 보관합니다. 소스 태그와 설치된 실행 파일의 버전은 다를 수 있습니다. 기존 원격 기록·예약과 제품 프로필은 그대로 유지합니다.
