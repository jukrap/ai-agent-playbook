# MCP 설정과 권한

MCP를 연결하면 에이전트 앱이 AAPB 기록 도구를 호출할 수 있습니다. 선택 사항이므로 CLI와 직접 파일 편집만 사용해도 됩니다. 패키지를 설치하는 것만으로 서버가 등록되거나 켜지지는 않습니다.

## 연결 전에 확인하기

CLI 동작을 확인한 설치본이나 소스를 사용합니다. 기존 프로젝트의 터미널 폴더에서 `ai-agent-playbook records status --json`으로 기록을 확인하세요. 기존 공통 MCP 설정이 있다면 실행 명령과 도구 허용 목록을 의도적으로 갱신하기 전까지 비활성 상태로 둡니다.

경로를 따로 지정하지 않으면 서버는 시작한 폴더를 프로젝트로 사용합니다.

```powershell
ai-agent-playbook mcp
```

통신 방식은 표준 입출력(stdio)입니다. 클라이언트와 서버가 표준 입력·출력으로 메시지를 주고받습니다. 터미널에서 직접 실행하면 클라이언트를 기다리느라 아무 반응이 없어 보일 수 있습니다. 이것만으로 로딩이나 기능을 확인한 것은 아닙니다. 수동 실행을 마치려면 Ctrl+C로 종료하세요.

Codex에서는 공통 등록 하나로 여러 프로젝트의 작업에 사용할 수 있습니다. Codex가 각 서버를 해당 작업의 폴더에서 시작하므로 저장소마다 프로젝트 경로를 입력할 필요가 없습니다. 연결은 시작한 폴더를 계속 대상으로 삼으며, 다른 저장소를 언급하거나 셸에서 폴더를 바꿔도 대상이 바뀌지는 않습니다. 공통 설정 전체 예시는 [Codex 설정](../adapters/codex/README.ko.md)에 있습니다.

## 앱에 설정하기

사용하는 앱이 지원하는 MCP 설정 형식에 다음 값을 넣습니다.

| 설정 | 값 |
| --- | --- |
| 서버 이름 | `aapb` |
| 실행 명령 | `node`. 앱에서 찾지 못하면 Node 실행 파일의 절대 경로 |
| 인자 | `bin/aapb.mjs`의 절대 경로, `mcp` 순서 |
| 통신 방식 | stdio |
| 환경 변수 | AAPB 기록 도구에는 API 키가 필요하지 않음 |

명령과 인자 부분의 예시는 다음과 같습니다.

```json
{
  "command": "node",
  "args": ["<absolute-package-directory>/bin/aapb.mjs", "mcp"]
}
```

패키지 폴더 자리표시자를 실제 경로로 바꾸고 인자는 각각 별도 배열 항목으로 둡니다. 이 예시는 명령 부분만 보여주며 앱별 완성 설정 파일은 아닙니다. 스크립트 절대 경로는 설치된 프로그램의 위치를 알려주고, 프로세스의 시작 폴더는 읽을 프로젝트 기록을 결정합니다. AAPB 서버가 이미 등록되어 있다면 같은 서버를 중복 등록하지 말고 기존 항목을 수정하세요. [Codex](../adapters/codex/README.ko.md), [Claude Code](../adapters/claude-code/README.ko.md) 안내도 참고할 수 있습니다.

## npx로 게시된 버전 실행하기

설치한 스크립트 경로 대신 npm의 패키지 실행기로 같은 서버를 시작할 수도 있습니다.

```json
{
  "command": "npx",
  "args": ["-y", "ai-agent-playbook@1.0.0", "mcp"]
}
```

기존 등록의 명령·인자를 바꾸는 대안입니다. 활성 상태, 도구 허용 목록과 의도한 작업 폴더는 유지하고 서버를 중복 등록하지 마세요. 앱에서 Node.js와 npm을 실행할 수 있어야 합니다. `-y`는 npm의 패키지 설치 확인 질문을 생략하고, `@1.0.0`은 실행할 패키지 버전을 지정합니다. 필요한 내용이 없으면 npm 캐시에 내려받을 수 있으며, 시작할 때마다 반드시 다시 다운로드하는 것은 아닙니다.

앱은 연결할 때 서버를 시작하며 도구를 호출할 때마다 다시 실행하지 않습니다. 버전과 프로젝트가 같으면 두 실행 방식의 AAPB 기능은 같습니다. 전역 CLI를 업데이트해도 npx에 지정한 버전은 바뀌지 않습니다. 다른 릴리스를 사용할 때 버전 지정을 수정하고 연결을 다시 불러오세요.

## 대상 경로를 고정해야 할 때

다른 클라이언트가 원하는 작업 폴더를 넘기지 않거나 특정 프로젝트를 의도적으로 고정하려면 `--project`와 절대 경로를 덧붙입니다.

```json
{
  "command": "node",
  "args": ["<absolute-package-directory>/bin/aapb.mjs", "mcp", "--project", "<absolute-project-directory>"]
}
```

터미널에서는 `ai-agent-playbook mcp --project "<project>"`와 같습니다. 서버 `cwd`를 지원하는 앱이라면 그 값으로 시작 폴더를 고정할 수도 있습니다. 혼동을 줄이려면 대상을 지정하는 방법은 하나만 사용하세요. Codex에서는 선택 사항이며, 저장소마다 연결 설정이 달라야 할 때 프로젝트별 설정을 사용할 수 있습니다. 다른 클라이언트도 Codex와 같다고 가정하지 말고 시작 폴더를 확인하세요. AAPB는 지정된 폴더를 그대로 사용하며 부모 Git 루트를 찾아 올라가지 않습니다.

## 실제 로딩과 호출 확인하기

앱에서 MCP 연결을 다시 불러온 뒤 도구 목록을 봅니다. AAPB 도구는 아래 네 개여야 합니다.

| 도구 | 목적 | 첫 요청의 인자 |
| --- | --- | --- |
| `aapb_status` | 기록 구조, 시작 문서, 총수 확인 | `{}` |
| `aapb_read` | 기록 하나 읽기 | `{"path":"CURRENT.md"}` |
| `aapb_search` | 기록 안에서 문자열 검색 | `{"query":"CURRENT.md에 있는 문구"}` |
| `aapb_validate` | JSON, 링크, 관리 파일 변경 확인 | `{}` |

상태와 읽기를 실제로 호출하고 원본 경로·경고·파일 내용을 대조하세요. 기록 검증의 `runtimeVerified: false`는 정상입니다. 설정 항목 존재, 프로세스 실행, 도구 목록 표시, 호출 성공은 서로 다른 확인 단계입니다.

이전 1.0 사전 릴리스는 `playbook_*` 이름을 사용했지만 next.2부터는 중복 별칭 없이 `aapb_*`를 제공합니다. 도구 허용 목록을 직접 정했다면 갱신하세요. npm 패키지 이름과 기록 폴더는 바뀌지 않습니다. CLI 축약 명령을 제공한다고 MCP 도구나 스킬이 늘어나는 것은 아닙니다.

SDK 호출 성공과 자연어 요청에서 에이전트가 도구를 선택하는 것의 차이는 [에이전트의 도구 활용](agent-usage.ko.md)에서 설명합니다.

## 읽을 수 있는 범위와 출력

도구 요청으로 연결된 프로젝트를 바꿀 수 없습니다. 읽기 경로는 플레이북 기준입니다. 프로젝트 밖으로 나가는 경로, 절대 경로 입력, 심볼릭 링크·junction, 읽기에 적합하지 않은 파일은 거부하거나 건너뛰었다고 표시합니다. 전체를 검사하지 못했다면 경고로 알립니다.

`.ai-agent-playbook/CURRENT.md`를 읽으려면 `{"path":"CURRENT.md"}`를 전달합니다. 기본 시작 문서는 `{}`만 전달해도 읽습니다. 도구 인자에는 `.ai-agent-playbook/`을 붙이지 않습니다. 다른 기록은 상태 조회나 검색 결과에 나온 상대 경로를 사용하세요.

본문은 기본 12,000자이며 조절할 수 있습니다. 긴 문서와 목록은 다음 부분을 요청할 커서를 반환합니다. MCP 결과 전체에는 별도로 UTF-8 기준 256 KiB 상한이 있습니다. 텍스트·구조화 표현과 부가 정보가 포함되며 JSON-RPC 전송 봉투는 제외합니다. 실제 크기 선택과 예시는 [응답 크기 안내](record-responses.ko.md)를 보세요.

## 쓰기와 문제 해결

MCP에는 쓰기 도구, 셸 도구, 동적 리소스, 생성형 작업 프롬프트, 자동 훅, Forge 쓰기가 없습니다. 기록은 평소처럼 파일을 편집하고, 이전이나 Forge 적용은 명시적인 CLI 명령으로 진행합니다. 과거의 쓰기 활성화 옵션은 지원하지 않습니다.

| 문제 | 대응 |
| --- | --- |
| 앱이 명령을 시작하지 못함 | Node·스크립트 절대 경로와 앱의 실행 환경 확인 |
| 예전 도구가 계속 보임 | 중복 서버 설정을 확인하고 연결 다시 불러오기 |
| 다른 프로젝트의 기록이 나옴 | 고정된 `--project`나 서버 `cwd`가 있는지 확인하고 의도한 프로젝트에서 작업 시작 |
| CURRENT.md가 없음 | 상태와 기존 구조 확인. Bootstrap으로 덮어써야 한다고 가정하지 않기 |
| 편집 후 커서가 거부됨 | 바뀐 원본을 기준으로 읽기·검색 다시 시작 |
| 결과가 너무 큼 | 검색 범위를 좁히거나 페이지 크기를 줄이거나 특정 문서·줄 범위를 읽기 |

연결을 꺼도 프로젝트 파일은 남습니다. 공통 MCP 활성화는 사용자가 별도로 선택합니다.
