# 디자인·UI·문장·코드 품질

서로 다른 검토 대상이며 하나의 AI스러움 점수로 합치지 않습니다.

디자인 방향은 제품 목적·참고 예시·브랜드·정보 밀도·구현 제약을 보존합니다. UI 다듬기는 실제 과제의 렌더링 상태와 접근성을 비교합니다. 도구 연결은 선택한 디자인 도구의 고유 지침을 따릅니다.

자연스러운 문서 편집은 의미·수치·명령·URL·용어·문체·의도적 강조를 유지합니다. 한국어 예시는 자동 치환 규칙이 아닙니다. 일반 편집에는 CLI 검사나 평가표가 필요하지 않으며 큰 재작성이나 명시적 요청에서만 검사를 참고합니다.

코드 정리는 불필요한 추상화·중복·동작 보존을 검토합니다. 예시는 선택 라이브러리에 두고 시각·문체 판정과 합치지 않습니다.

소설의 승인된 문체·인물 말투·장르 관습은 집필 제품이 관리합니다. 일반 문서 규칙으로 원고를 바꾸지 않습니다. 카드·그라데이션 등 시각 요소는 의도적이고 유용할 수 있습니다.

작은 비교에서는 입력·제약·모델 설정·완료 기준을 같게 두고 정보 보존·과제 적합성·과잉 교정·관측 비용을 별도로 기록합니다. 소규모 사례로 일반적인 성능 향상을 증명했다고 하지 않습니다.
