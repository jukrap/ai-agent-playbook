# AAPB 기록 응답 규격

공개 MCP 이름은 aapb_status, aapb_search, aapb_read, aapb_validate입니다. 이전 사전 릴리스의 playbook_* 이름은 더 이상 노출하지 않습니다. 명시적 도구 허용 목록이 있다면 이번 사전 릴리스에 맞춰 갱신하세요. npm 패키지명, aapb 명령과 기존 기록 디렉터리는 유지합니다.

## 예산과 이어 읽기

기본 내용 예산은 12,000자이며 maxChars로 최대 100,000자까지 조절합니다. 목록은 완전한 항목 20개가 기본이고 pageSize는 최대 100개입니다. 검색은 기존 maxResults를 페이지 크기 옵션으로 유지합니다. 이는 내용 예산이며 토큰 추정치가 아닙니다. 두 표현과 메타데이터를 포함한 MCP 결과 전체에는 별도로 UTF-8 기준 256 KiB 상한을 적용합니다. 이 값은 방어적 상한이며 목표 출력량이나 호스트의 토큰 설정이 아닙니다.

상태의 기본 응답은 짧은 요약이며 records·warnings 보기는 페이지로 나눕니다. 검증은 문제 목록 페이지가 기본이고 summary·warnings 보기도 제공합니다. 모든 보기에 검사 완료 여부와 검사한 범위 내 총수를 유지합니다. 페이지를 나눠도 실패한 검증을 성공으로 바꾸지 않습니다. 완전한 항목 하나도 담을 수 없는 작은 예산은 JSON 조각 대신 조정 가능한 오류를 반환합니다.

검색은 원본 경로·줄 번호·검색어 주변 문맥을 반환합니다. 읽기는 줄바꿈을 포함한 원문 조각, 원본 해시와 정확한 이어 읽기 위치를 제공합니다. 긴 줄과 Unicode 쌍도 누락·중복 없이 이어 읽습니다. 첫 읽기에는 startLine/endLine을 사용할 수 있습니다. 반환된 커서가 이어 읽을 범위를 기억하므로 후속 요청은 같은 path를 사용하며 maxChars는 바꿀 수 있습니다.

목록의 다음 페이지는 같은 검색어·보기를 유지하며 nextCursor를 전달합니다. 커서는 프로젝트·작업·검사한 내용에 묶입니다. 원본이 바뀌거나 요청이 맞지 않으면 커서를 거부합니다. 누락·중복을 숨기지 않고 조회를 다시 시작해야 합니다. 커서는 내부 구조를 해석하지 않는 이어 읽기 데이터이며 권한을 부여하지 않습니다. 매 요청마다 파일 경계를 확인합니다.

## 검사 경계와 근거

파일 하나는 500,000바이트, 탐색은 2,000개 항목, 요청별 텍스트 검사 합계는 32 MB로 제한합니다. 검색 결과와 검증 문제는 각각 10,000개까지 검사하며 상한에 도달하면 불완전한 검사임을 표시합니다. 건너뛰거나 읽지 못하거나 검사하지 않은 범위는 scan 메타데이터와 경고에 남깁니다. 서버는 현재 대화의 남은 토큰 예산을 알지 못하며 추측하지 않습니다.

이 이어 읽기는 AAPB 도구의 인자·결과 규격입니다. [MCP 목록 페이지 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination)이 tools/call 결과를 자동으로 나눠 주는 것은 아닙니다.

응답 크기 검사에서 원본 기록을 요약하거나 다시 쓰지 않습니다. MCP 호출은 결과 캐시나 임시 보고서 파일을 만들지 않습니다. 검증 결과는 설정·문서 검사이며 runtimeVerified는 false로 유지합니다.

## 검증과 시연

원문 재조립, 안정적인 목록 페이지, 원본 변경 커서, 검색어·프로젝트 불일치, 작은 예산, 경고 노출, Unicode와 최종 직렬화 크기를 검사합니다. 실제 SDK stdio 클라이언트도 사용합니다.

레지스트리 게시 전에 로컬 npm 압축 파일을 격리된 prefix에 설치합니다. 기존 프로젝트 기록으로 상태·검색·읽기·검증·이전 미리보기를 시연합니다. 적용·복구는 보존한 기록 복사본에서 시연합니다. 개인 실행 결과와 프로젝트 세부 정보는 공개 배포물에서 제외합니다. 영어·한국어 명령 이름, 한도, 이전 안내와 검증 주장을 같은 변경에서 대조합니다.
