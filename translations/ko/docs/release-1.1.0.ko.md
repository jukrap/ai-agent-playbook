# AI Agent Playbook 1.1.0

1.0의 작은 스킬·기록 구조를 유지하면서 읽기 전용 AST 소스 검색을 복원했습니다. 구조 파싱은 실제 코드 검색 능력을 제공하므로, 개편 때 정리한 일반 절차 지침과 구분해 다시 제공합니다. 이전의 전체 심층 분석, 언어 서비스, 예약 실행과 코드 교체 명령은 계속 종료 상태입니다.

## 달라진 점

- `ai-agent-playbook ast search`로 언어를 지정하고 프로젝트 상대 경로를 선택해 구조 패턴을 검색합니다.
- MCP를 `--with-ast`로 시작하면 `aapb_ast_search`를 추가합니다. 기본 연결은 기록 도구 네 개, 개발 스킬 프로필은 다섯 개를 유지합니다.
- 선택 의존성 `@ast-grep/napi`는 AST 호출 때만 로딩합니다. 일반 npm 설치에는 지원 플랫폼의 네이티브 모듈이 포함됩니다. `--omit=optional`로 제외해도 기록 도구는 사용할 수 있습니다.
- 결과에는 정확한 소스 위치, 길이를 제한한 코드 조각, 이어 읽기와 검색 범위가 포함됩니다. 원본이 바뀐 커서와 링크 경로를 거부하며, 탐색 중 발견한 링크는 대상을 읽지 않고 건너뜁니다.

## 업데이트와 사용

```powershell
npm install -g ai-agent-playbook@1.1.0 --include=optional
ai-agent-playbook --version
ai-agent-playbook ast search --lang javascript --pattern 'console.log($$$ARGS)' --path src --json
```

검색은 원하는 프로젝트의 터미널에서 실행합니다. PowerShell과 POSIX 셸에서는 작은따옴표로 패턴의 메타변수를 보호합니다. 지원 언어, 제외 경로, 파일 제한, 이어 읽기와 엔진 누락 처리는 [AST 검색](ast-search.ko.md)에 있습니다.

기존 MCP 등록은 기본 기록 도구 네 개를 유지합니다. AST를 쓰려면 `mcp` 뒤에 `--with-ast`를 추가하고, 도구 허용 목록이 있으면 `aapb_ast_search`도 넣은 뒤 연결을 한 번 다시 불러오세요. 기존 `npx -y ai-agent-playbook@latest mcp` 등록은 패키지 선택자를 유지해도 됩니다. 실행 중인 프로세스는 재시작 전까지 로딩한 버전을 사용하므로, 레지스트리 게시와 실제 호스트 로딩은 따로 확인해야 합니다. 전체 설정은 [MCP 안내](mcp-permission-model.ko.md)를 참고하세요.

스킬 재설치, 기록 이전, 아키텍처 재작성이나 새 공통 정책은 필요하지 않습니다. 패키지 설치가 MCP 설정을 자동으로 바꾸지는 않습니다. 기존 1.0 기록과 Forge 협업 기능도 호환됩니다.

## 검증과 한계

로컬 Windows에서 Node.js 22.22.3 전체 테스트 154개, Node.js 18.20.8의 AST·MCP 검사 16개와 정적·타입·Python·문서 검사, 설치 미리보기가 통과했습니다. 선택 엔진을 포함하거나 제외한 패키지 설치를 시험했고, 두 기존 프로젝트에서 CLI와 SDK stdio 검색 결과가 일치하며 소스·기록이 바뀌지 않음을 확인했습니다. Node 18 검사에서 발견한 Windows junction 처리 차이도 보완했습니다.

구조 일치는 타입을 이해한 참조 추적이나 실행 동작의 증명이 아닙니다. 모든 호스트의 자동 도구 선택, 모든 플랫폼의 네이티브 호환성, 속도·토큰 개선을 입증한 결과도 아닙니다. 전체 검색 계약과 확인한 한계는 [AST 검색](ast-search.ko.md)에 있습니다.

## 복구

이전 런타임으로 돌아가려면 `ai-agent-playbook@1.0.0`을 설치합니다. 구버전 서버를 다시 시작하기 전에 등록에서 `--with-ast`와 `aapb_ast_search`를 제거하세요. 런타임 버전만 바꿨다는 이유로 기존 기록이나 바뀌지 않은 스킬 파일까지 복원할 필요는 없습니다. MCP도 이전 버전을 유지해야 한다면 `npx`의 패키지 버전을 정확히 지정합니다.
