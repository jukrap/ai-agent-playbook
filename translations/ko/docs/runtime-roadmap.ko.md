# 정식 버전 준비

현재 소스는 1.0 사전 릴리스입니다. 정식 버전 준비는 버전 번호나 줄어든 스킬 수만으로 판단하지 않습니다. 실제 동작과 사용자가 따라갈 수 있는 도입 경로를 확인해야 합니다. 이미 모은 근거는 [검증 보고서](verification.ko.md)에 있으며, 이 문서는 남은 릴리스 판단 기준을 설명합니다.

## 준비 상태를 볼 항목

| 영역 | 검토할 근거 |
| --- | --- |
| 런타임 | 필수 정적·타입·테스트·Python 검사와 공개 명령 호환성 |
| 기록 | 최소 생성, 구버전 읽기, 현재 사실과 근거 링크 보존 |
| 설치 | 프로필 선택, 관리 파일 보존, 미리보기, 중단 복구, 반복 복원 |
| MCP | 도구 네 개, 제한된 읽기 전용 호출, 실제 stdio 통신과 앱 로딩 |
| Forge | 식별자 유지, 오래된 상태 충돌, 일부 실패, 실제·모의 검증 구분 |
| 사람용 문서 | 초보자 실습, 명령 예시, 문제 해결, 언어별 표현, 이해할 수 있는 한국어 |
| 패키지 | 실제 압축 파일, 이미지·링크, 격리 설치, 정확한 버전과 체크섬 |
| 공통 환경 | 설치 수, 발견 목록, 대화에 들어간 지침, 실제 도구를 각각 측정 |

## 사전 릴리스에서 정식 버전으로

보존, 명령 정확성, 처음 사용 경로에 영향을 주는 문제를 먼저 해결합니다. 수정 후 관련 검사를 다시 합니다. 이후 [배포 점검표](publishing-checklist.ko.md)에 따라 Node/Python 버전, 변경 기록, 이전 안내, 검토한 압축 파일을 준비합니다.

GitHub 병합은 npm 게시가 아니며 압축 파일 설치에 레지스트리 게시가 필요하지 않습니다. 릴리스 대상으로 확인한 파일을 정확히 기록하고 이전 런타임과 백업을 보존하세요. 한 번의 로컬 실행이나 CI 통과만으로 모든 플랫폼과 앱을 검증했다고 하지 않습니다.

## 이번 릴리스 밖의 작업

예전 기능 수에 맞추려고 실행·예약·광범위 분석을 다시 넣지 않습니다. Writer/Game 전문 기능은 별도 제품 계획과 실행 계약을 따릅니다. 실험적인 history/notes 기능은 일반 기록 사용의 필수 의존성이 아닙니다.

추가 기능은 실제 부족한 역할을 채워야 하며 기록이나 공개 명령을 바꾸면 이전 방법도 마련합니다. 도입을 이해하기 쉬워진다면 사람용 안내는 길어질 수 있습니다. 지침 축소를 문서 분량 목표로 삼지 않습니다.
