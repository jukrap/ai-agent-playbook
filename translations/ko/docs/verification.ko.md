# 1.0 사전 릴리스 검증

## 범위와 런타임 검사

이번 릴리스는 프로젝트 기록, 선택 스킬, 설치와 로컬 기능 노출을 바꿉니다. Writer와 Game에는 별도 로컬 계획만 작성했습니다. 기존 미커밋 파일 해시, 저장소 HEAD와 worktree 목록을 보존했으며 두 제품 구현과 실제 게임 엔진 실행은 이번 검증 대상이 아닙니다.

개편한 테스트는 Windows와 Node.js 22.22.3에서 128개 모두 통과했습니다. 이 중 25개는 새 CLI·기록·설치/복구·실제 stdio MCP를 검증하고, 103개는 Forge와 Python 탐색의 기존 검사를 유지합니다. 이전 458개 통과·1개 건너뜀 기준선에는 종료한 실행·인덱싱·예약 기능이 포함되어 있으므로 총수를 성능이나 커버리지 비교로 사용하지 않습니다.

정적·TypeScript·스킬·번역·공개 문서·Python 검사도 통과했습니다. 새 검사 25개는 Node.js 18.20.8에서도 통과했습니다. 이는 호환성 확인이며 모든 지원 OS·Node 버전에서 전체 검사를 실행했다는 뜻은 아닙니다. Windows/Ubuntu CI 행렬은 준비했지만 원격으로 실행하지 않았습니다.

배포 준비 후속 점검에서 명시한 백업과 설치가 다른 볼륨에 있을 때 EXDEV 실패를 재현했습니다. 기본 백업이 선택한 설치 경로를 따르도록 바꿨고, 파일시스템이 다른 백업 조합은 쓰기 전 미리보기·적용에서 거부합니다. 회귀 검사에서 서로 다른 Windows 볼륨과 같은 파일시스템의 기본 설치·복구를 확인했습니다. 파일시스템을 넘는 원자적 복사는 지원하지 않습니다. next 태그의 npm 게시 미리보기도 통과했지만 레지스트리 권한이나 실제 게시 성공을 확인한 것은 아닙니다.

설치 검사는 단일 경로, 프로필 선택, 한글·공백 경로, 미관리·수정 파일, junction 경계, 동시 편집, 중단된 적용, 잘못된 복구 기록, 변조된 백업, 이전·복구 재실행을 포함합니다. 기록 검사는 구버전 레이아웃, 최소 생성, 무변경 미리보기, 관리 메타데이터와 복원을 확인합니다. MCP는 SDK stdio 클라이언트로 도구 네 개, 경로 이탈 거부, 직렬화 출력 제한과 기록 무변경을 확인했습니다. Forge는 모의 전송으로 기존 식별자, 오래된 상태 충돌과 부분 실패를 검증했으며 원격 기록을 쓰지 않았습니다.

추가 검수에서 빈 명시적 스킬 선택, 읽을 수 없는 현재 상태 진입점, --root를 무시하는 문서 보고서, 선택형 검사의 상위 링크 경로 문제를 재현하고 수정했습니다. 회귀 검사에서 프로젝트 기록과 외부 파일을 바꾸지 않고 잘못된 입력을 거부합니다. MCP 검사는 텍스트·구조화 표현을 모두 포함한 최종 도구 결과를 확인합니다. 각 표현을 따로 검사할 때 놓쳤던 합산 한도 문제를 보완했습니다. npm 파일 목록에는 한국어와 연결된 유지보수 문서를 포함했으며, 현재 안내·스킬 Markdown 106개의 상대 링크와 개인 기록·백업·테스트 제외를 확인했습니다.

로컬 패키지에는 필요한 런타임·목록·참조 파일이 포함되고 개인 기록은 제외됐습니다. 별도 npm prefix에서 기존 전역 패키지 0.5.10 실행, 1.0.0-next.1 업그레이드, 0.5.10 복구, 재업그레이드가 성공했습니다. 소스 복구 기준은 별도로 0.5.11입니다. npm 게시와 원격 push는 수행하지 않았습니다.

## 다섯 사례 비교

산출물만 생성하는 열 번의 호출에 같은 Astra 모델, xhigh 추론과 명시적 컨텍스트·출력 설정을 사용했습니다. 두 조건의 개인 지침도 동일합니다. 기본 조건은 과제와 원문을, 경량 조건은 해당 짧은 스킬과 선택 참조를 추가로 받았습니다. 비교 호출에서만 자동 스킬 목록 주입과 플러그인·앱 도구를 비활성화했고 공통 모델·예산 설정은 보존했습니다.

UI는 정보가 많은 출고 화면과 의도적인 브랜드 표현이 있는 서점 행사 화면을 가상 HTML로 구성했습니다. 문서는 보호할 문자열이 있는 기술 안내와 친근한 독서 모임 공지입니다. 코드는 공개 함수의 관찰 가능한 동작을 유지하면서 중복 헬퍼를 제거하는 사례입니다.

조건별 한 번의 실행은 이 예시를 검토하는 자료이며 일반적인 효과를 추정하지 못합니다. 블라인드 평가, 여러 시드의 벤치마크나 전체 에이전트 작업 흐름 비교가 아닙니다. 두 프롬프트 모두 도구와 확인 질문을 금지했으므로 도구 호출 0회로 질문·재독해·검사 비용의 감소를 입증할 수 없습니다.

출력 토큰은 별도로 표시된 추론 출력을 포함하는 CLI의 총수입니다. 캐시 입력은 경량 기술 문서 실행의 11,008토큰 외에는 0입니다. 경과 시간에는 서비스 지연이 포함됩니다. 이 수치나 구독 사용률로 금액 절감을 계산하지 않습니다.

UI 결과는 앱 내 Chromium 브라우저의 1440px·390px에서 확인했습니다. 검색·필터, Enter/Escape 진입·복귀와 포커스 복원, 빈 폼 검증, 가상 입력 접수를 실행했습니다. 390px에서 페이지 가로 넘침은 없었습니다. 전체 접근성 감사나 실제 모바일 기기 검증은 아닙니다. 출고 화면 두 결과 모두 간단한 원문보다 로컬 송장 초안 기능이 늘었으며 추가 지침이 구현 확대를 일관되게 줄이지는 못했습니다.

코드 비교에는 엄격한 boolean 선택, nullish 기본값, 순서·중복, 배열 외 iterable, getter 횟수, 문자열 변환과 예외를 포함했습니다. 문서는 보호 문자열 검사와 의미·문체에 대한 검토를 함께 사용했으며 작성 주체를 판별하지 않았습니다.

## 반영한 판단과 한계

과제별 제약과 예시를 제공하는 짧은 디자인·UI·문서 진입점은 유지합니다. 코드 정리는 별도 선택 참조로 남깁니다. UI와 코드에서 일관된 이득이 확인되지 않았으므로 긴 지침은 선택 사항으로 두고, 작고 명확한 UI·문서 편집에서는 참조를 필수로 읽지 않도록 바꿨습니다. 이 마지막 선택 참조 문구는 비교 뒤 조정했으며 별도 모델 비교를 다시 수행하지 않았습니다.

새 호스트의 발견과 실제 프롬프트 주입을 구분해 측정했습니다. 구현 환경의 관리 AAPB 설치본은 이전 전 188개, 개발 프로필 적용 후 5개입니다. 독립 작업 190개를 충돌 없이 적용했고 재실행은 0개를 제안했습니다. 원격 플러그인을 로딩한 호스트는 활성 스킬 50개를 발견했고 실제로는 서로 다른 44개를 주입했습니다. 초기 세션의 262개 항목·같은 이름 중복 88개와 구분되는 결과입니다. 44개는 선택·사용자 관리 35개, 앱 번들 4개, 주입된 시스템 스킬 5개입니다. 발견 목록에는 자동 주입하지 않는 항목도 포함됩니다.

원격 플러그인을 아직 로딩하지 않은 첫 CLI 턴은 20개만 주입했습니다. 이는 로딩 시점의 차이이며 추가 정리 성과가 아닙니다. 캐시·발견·주입 목록·연결 도구를 같은 수치로 취급하지 않습니다. 기존 대화에는 이전 컨텍스트가 남습니다. 원격 플러그인 제어는 [환경 프로필](environment-profiles.ko.md), 복구는 [설치 생명주기](lifecycle.ko.md)를 참고하세요.

공통 AAPB MCP와 공통에 있던 프로젝트 전용 MCP는 새 런타임에서 비활성 상태를 확인했습니다. 선택하지 않은 플러그인 MCP 오버레이도 비활성입니다. 호스트 커넥터 도구는 연결을 유지하며 도구 노출만으로 모든 커넥터 동작이나 산출물 렌더러를 검증했다고 보지 않습니다. history/notes는 공개 코드·모델 정보만으로 가용 상태를 승격하지 않았고 실험 설정도 켜지 않았습니다.
