# 모듈 간 공개 인터페이스

index 파일, export, 라우트 로더, 기능 API, 컴포넌트 라이브러리나 공유 모듈이 경계를 나타낼 때 사용합니다.

## 계약 확인하기

- 호출부가 가져올 수 있는 항목과 내부에 둘 항목을 구분합니다.
- export, 라우트, 생성된 API 파일, 별칭, package exports와 경로 대응을 확인합니다.
- 공개 계약에 포함되는 이름, 타입, 기본값, 부수 효과, CSS·자산과 tree-shaking 동작을 보존합니다.
- 이전이 필요한 호출부와 호환용 재노출의 필요성을 확인합니다.

## 경계를 바꾸기

구조를 이전할 때는 이상적인 최종 트리로 전부 옮기기보다 다음에 바꿀 의미 있는 범위를 고릅니다. 호출부를 전환하는 동안 필요한 어댑터를 유지합니다. 폴더 이름만 바꾼다고 의존성 방향이나 담당 범위가 좋아지는 것은 아닙니다.

채택한 설계를 바꾸면 [아키텍처 결정](../../../docs/project-architecture.ko.md)을, 인터페이스가 workspace 패키지를 넘으면 [패키지 경계](../monorepo-package-boundary/package-ownership-dependency-direction.ko.md)를 참고합니다.

진입점을 없애기 전에는 호출부를 확인합니다. 생성된 라우트나 파일을 옮기기 전에는 생성기와 실행 환경을 검증합니다. 문서와 import가 다르면 차이를 기록하고 관련 계약을 정리합니다. 현재 코드를 의도한 설계로 조용히 바꾸어 해석하지 않습니다.
