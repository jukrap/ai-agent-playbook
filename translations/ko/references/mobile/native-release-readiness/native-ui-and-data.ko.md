# 네이티브 UI와 데이터 경계

실제 React Native 또는 Expo 애플리케이션에 네이티브 관련 지침이 필요할 때 사용합니다. 의존성 이름만 보고 Expo Router, 패키지 관리자나 웹 방식의 아키텍처를 추정하지 않습니다.

- 앱 설정, 라우터, 네이티브 폴더, 설치된 SDK와 빌드 프로필을 확인합니다. 라우트 모듈은 실제 라우터 계약에 맞게 유지합니다.
- 기존 React Native 스타일·테마 규칙을 사용합니다. 웹 CSS 전제가 네이티브 UI에 그대로 적용되는 것은 아닙니다. WebView/DOM과 네이티브의 역할을 구분합니다.
- 권한, 네이티브 모듈, 딥 링크, 알림과 브리지 계약은 담당 모듈을 분명히 합니다. 생명주기와 플랫폼 영향을 일반 유틸리티 안에 숨기지 않습니다.
- API 응답 계약과 기존 서버 상태 관리 도구를 확인합니다. 네트워크 실패, 권한 거부, 오프라인 동작과 재시도를 고려합니다.
- AsyncStorage, SQLite, SecureStore 등 저장 방식을 바꾸기 전에 관리 주체와 데이터 이전을 확인합니다.
- 영향을 받는 플랫폼에서 관련 안전 영역, 키보드 상호작용, 글자 크기, 터치 영역, 방향 전환과 스크롤을 확인합니다. [기기 상태 검사](../device-permission-qa/lifecycle-and-device-state-checks.ko.md)에서 필요한 시나리오를 고릅니다.
- 실제 확인한 플랫폼과 빌드 프로필을 기록합니다. 개발 클라이언트, EAS, 네이티브 바이너리와 업데이트 채널의 영향은 [빌드 채널 안내](mobile-build-channel-checks.ko.md)를 참고합니다.

필요한 계약을 골라 확인하는 참고 자료입니다. 새 폴더 구조를 강제하거나 매번 모든 기기 시나리오를 실행하도록 요구하지 않습니다.
