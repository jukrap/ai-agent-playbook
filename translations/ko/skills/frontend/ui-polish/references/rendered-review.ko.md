# 렌더링된 화면 검토

같은 viewport·데이터·상호작용 상태를 비교합니다. 미적 점수보다 사용자 영향을 먼저 봅니다.

- 중요한 정보와 주요 행동을 빨리 찾을 수 있는가?
- 작업과 콘텐츠 양에 맞는 정보 밀도인가?
- 계층·간격·텍스트·스크롤·반응형 우선순위가 안정적인가?
- 관련된 키보드·focus·이름·대비·모션 감소가 동작하는가?
- 로딩·빈 화면·오류·비활성 상태를 색상 외의 단서로도 읽을 수 있는가?

카드·pill·그림자·그라데이션·둥근 모서리는 적절할 수 있습니다. 반복이 계층을 가리거나 작업 공간·정보를 손상하거나 실제 제품 제약과 충돌할 때 문제입니다.

예: 의미 있는 세 상태의 브랜드색 pill은 남기고 테이블 행동을 아래로 밀어내는 장식 pill은 줄입니다. 모든 패널을 평평하게 만들지 않고 유용한 카드 경계를 보존합니다.

정적 검사 후보는 실제 화면에서 확인한 뒤 고칩니다. 실제 확인한 viewport와 상태만 보고합니다. screenshot만으로 키보드 동작을 검증했다고 하지 않습니다. 작은 편집을 위해 새 도구 체계를 추가하지 않고 프로젝트의 브라우저·테스트 도구를 재사용합니다.

코드 구조와 문장 편집은 별도 과제입니다. UI 문구는 과제의 명료성과 구체성에 영향을 줄 때 여기서 봅니다.
