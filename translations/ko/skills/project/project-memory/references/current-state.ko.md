# 현재 상태

동일 내용을 동기화하는 요약 묶음 대신 하나의 현재 진입점을 사용합니다.

## 위치 확인과 읽기

프로젝트의 기존 진입점부터 확인합니다. 작업 공간의 공통 기록은 명시적으로 등록된 구성원에만 적용됩니다. 상위 폴더, 형제 저장소나 symlink/junction이 있다는 사실은 등록 근거가 아닙니다. 기록 선택과 코드 선택을 구분하세요. 코드나 Git 작업 전에 선택한 구성원, 해당 지침과 루트를 확인하고 Git이 있으면 브랜치와 미반영 변경도 확인합니다. 작업 공간 루트에서 코드 대상이 불명확하면 먼저 대상을 정합니다.

현재 진입점과 작업에 관련된 링크를 읽습니다. 제공되는 저장소, 주제, 월, 종류나 경로 필터와 제한된 페이지로 범위를 더 좁힙니다. 결과가 잘렸다면 빠진 부분을 다시 읽고 근거가 부족할 때만 범위를 넓히세요. 참고 자료 링크가 있다는 이유로 모든 이력을 읽을 필요는 없습니다. 무언가 없다고 판단할 때는 검색 범위와 제외한 부분을 밝힙니다.

구성원 저장소의 기존 로컬 기록은 별도 출처로 유지합니다. AAPB에서 `recordSource='repo:<id>'`를 명시하면 등록된 구성원의 기존 기록을 선택합니다. 이 선택은 파일을 옮기거나 코드 대상을 정하지 않습니다. Git이 없는 프로젝트를 포함해 기존 구조와 로컬 전용 규칙을 따릅니다.

## 필요한 내용

- 현재 목표와 구체적인 다음 행동
- 구현·전달 방식을 바꿀 수 있는 사용자 제약
- 소스 경로·명령 결과·명시적 결정으로 확인한 상태
- 관련 명세·결정·계약·미해결 문제의 링크

## 기록별 역할

| 기록 | 목적과 갱신 기준 |
| --- | --- |
| CURRENT.md | 현재 목표, 중요한 제약, 진행 상태, 다음 행동과 링크를 둡니다. 오래된 상태를 교체하고 진입점은 짧게 유지합니다. |
| 주제별 지식 문서 | 현재 유효한 규칙, 용어와 계약을 둡니다. 적용 저장소, 근거 위치, 확인 날짜와 확정·가정·미확인 상태를 표시합니다. 오래된 주장은 사용하기 전에 다시 확인합니다. |
| 날짜별 작업 일지 | 배경, 판단 근거, 변경, 영향받은 저장소, 결정, 가정, 실제 검사, 미검증 범위와 남은 일을 상세히 기록합니다. 커밋 제목 수준으로 줄이지 않고 재현 가능한 근거를 보존합니다. |

새 AAPB 기록에서는 기록 루트를 기준으로 주제 문서는 `knowledge/`에, 날짜별 일지는 `worklogs/YYYY-MM/`에 둡니다. 월별 폴더나 주제 문서는 처음 필요할 때 만듭니다. 월별 폴더가 있다고 해서 월간 요약을 작성할 필요는 없습니다. 이전이 허용되지 않았다면 예전 `workflows/worklogs/`와 다른 기존 구조를 보존하세요. 확인한 현재 지식은 판단 배경을 담은 과거 일지와 연결하되, 같은 이력을 CURRENT.md에 복사하지 않습니다.

저장소별 현재 상태 문서는 독립적인 진척을 관리해야 할 때만 추가합니다. 공통 진입점에서 연결하고 모든 구성원의 상태를 반복하지 않습니다. 공통 현재 상태 문서는 담당자를 하나씩 정하며, 병렬 작업자는 별도 초안이나 고유한 이름의 일지를 사용합니다.

## 갱신 예시

이전: “기능 구현 중.”
이후: “parser가 새 필드를 읽으며 호환성 검증이 남았습니다. 기존 공개 응답 형식을 유지합니다. 다음은 parser 계약 테스트입니다.”

오래된 사실을 새 타임라인 뒤에 덧붙이지 말고 교체합니다. 긴 출력과 개인 경로는 공개 문서가 아닌 로컬 근거에 보관합니다. 링크된 상세 내용은 필요할 때 읽습니다. 코드는 확인한 구현의 근거이고, 채택한 계약은 의도한 동작의 기준입니다. 과거 계획을 새 지침으로 삼거나 구현이 다르다는 이유로 채택한 요구사항을 버리지 말고 충돌을 알립니다.
