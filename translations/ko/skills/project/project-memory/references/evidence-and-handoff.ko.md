# 근거와 인수인계

중요한 결정에는 선택한 동작·이유·영향받는 계약·근거 위치·남은 불확실성·다음 행동을 기록합니다. 대안은 실제 절충을 설명할 때만 남깁니다.

완료·잔여 작업, 보존할 제약, 근거를 다시 확인할 파일·명령을 전달하고 대화 전체를 중복하지 않습니다.

## 의미 있는 진척의 작업 일지

단계가 끝났거나 중요한 결정·원인이 확인되었을 때, 또는 차단·중단·인계를 다음 세션까지 보존해야 할 때 기록합니다. 대화 전체를 복원하지 않고도 이어서 작업할 수 있도록 배경, 판단 근거, 영향받은 저장소, 바뀐 동작, 결정과 가정, 정확한 검사와 결과, 미검증 범위와 다음 행동을 충분히 남깁니다. 관련성이 있고 보관이 허용되는 경로, 소스 범위, 수치, 명령과 URL은 정확히 보존합니다.

프로젝트의 기존 작업 일지 위치와 이름 규칙을 사용합니다. 새 AAPB 일지는 `worklogs/YYYY-MM/` 아래에 날짜, 시간, 고유 ID와 주제가 포함된 파일명으로 만듭니다. 지원되는 작성 도구가 있으면 배타적 생성 기능을 사용하고, 없으면 고유한 이름을 골라 다른 작업자의 일지를 덮어쓰지 않습니다. 원시 출력과 비공개 근거 위치는 승인된 로컬 근거 보관 장소에 둡니다. 기록 작업을 요청받았다고 해서 Git 제외 규칙 변경, 과거 기록 이동이나 게시까지 허용되는 것은 아닙니다.

## 근거 구분

- 설정됨: 설정이나 도구 등록이 존재합니다.
- 로딩됨: 호스트에 실제 기능이 노출됩니다.
- 실행됨: 특정 환경에서 특정 과제를 수행했습니다.
- 검증됨: 완료 조건을 실제로 확인했습니다.

부재 주장은 검색 범위와 제외 파일을 밝힙니다. 생성 보고서와 과거 요약을 새 정책으로 삼지 않습니다. 확인하지 못하면 unknown으로 남깁니다. 지속적인 결정이 없는 작은 편집마다 기록을 요구하지 않습니다.

검증을 재사용할 수 있는 입력과 실행 조건을 기록합니다. 이 조건이 같고 프로젝트 필수 검사 규칙이 허용하면 통과한 결과를 기존 근거라고 표시해 재사용할 수 있습니다. 입력이 달라졌거나 실패, 미해결 우려 또는 새로 실행해야 하는 필수 검사가 있으면 그에 맞게 검증합니다. 초안에 명령을 설명했다는 사실은 실행 근거가 아닙니다.

## 선택적인 독립 초안 작성

기록은 보통 메인 작업에서 직접 갱신합니다. 조율과 검토에 드는 부담보다 이점이 큰, 길고 독립적인 초안 작업만 위임합니다. 호스트에서 지원하는 기능을 사용하고 사용자의 모델·추론 강도 선택과 명시적 역할 설정을 보존하세요. 기능이 없으면 메인 작업에서 기록을 마칩니다.

전체 대화 대신 범위를 정한 근거 묶음과 짧은 관련 이력을 전달합니다.

- 요청한 산출물, 독자, 저장 위치와 적용 저장소 ID
- 현재 목표, 허용 범위, 로컬 전용 제약, 채택한 결정과 필요한 최근 맥락
- 정확한 소스 경로와 범위, 값과 단위, 명령과 관측 결과, URL과 근거 날짜
- 가정, 모순, 미확인 사항, 생략한 검사, 남은 일과 허용된 읽기·쓰기 범위

응답이나 별도 담당 파일에 DRAFT임을 명확히 표시한 초안을 요청합니다. 공통 CURRENT.md와 채택한 지식 문서는 담당자를 하나씩 유지합니다. 초안 작성자는 직접 게시하거나 자신의 주장을 확정된 사실로 승격하지 않습니다. 역할 지침은 업무 범위를 정하며, 실제 접근과 격리는 호스트 권한이 결정합니다.

반영 전에 메인이 원래 근거와 대조하여 출처 경로와 범위, 수치와 단위, 명령, URL, 결정, 미확인·미검증 상태를 확인합니다. 불일치는 해결하거나 미해결로 명시합니다. 그 뒤 적절한 작업 일지, 지식 문서나 현재 상태를 갱신하되 초안 전체를 여러 곳에 반복하지 않습니다. 작성 에이전트가 성공을 보고해도 검토하지 않은 초안은 DRAFT로 남습니다.
