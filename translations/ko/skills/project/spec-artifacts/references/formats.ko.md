# 선택한 산출물의 형식

저장소 템플릿을 우선하고 결정 규모에 맞게 필드를 줄입니다.

| 산출물 | 필요한 내용 |
| --- | --- |
| 명세 | 문제·의도한 동작·제약·완료 조건 |
| ADR | 결정·이유·관련 대안·결과 |
| 계약 | 생산자/소비자·기존/새 형식·호환성·실패 동작 |
| 이전 | 시작 상태·미리보기·적용·충돌·검증·복구 |
| 인수인계 | 완료·잔여·제약·근거·다음 행동 |
| 릴리스 노트 | 사용자에게 달라진 점·호환성·필요한 조치·한계 |
| 검증 기록 | 명령/관찰·환경·결과·제외한 범위 |
| 작업 일지 | 배경, 판단 근거, 변경, 영향받은 저장소, 결정과 가정, 실제 검증, 미검증 범위, 다음 행동 |
| 주제별 지식 문서 | 현재 규칙이나 계약, 적용 저장소, 출처, 확인 날짜, 확정·가정 상태, 미확인 사실 |

선택 필드의 부재를 차단 조건으로 만들지 않습니다. 결과를 바꾸는 결정만 질문으로 남깁니다. 계약은 실제 출처를 명시하며 이름만으로 schema를 만들지 않습니다. 검증표는 구현을 줄마다 되풀이하지 않고 의미 있는 위험을 확인합니다.

## 근거와 기록 위치

의도한 동작과 현재 코드·관측 결과를 구분합니다. 다르면 채택한 요구사항을 보존하고 차이를 기록하세요. 영향을 받는 산출물에 필요한 출처부터 읽고 근거가 부족할 때만 넓힙니다. 전역 참고 자료와 과거 작업 일지에 링크가 있다고 해서 전체 이력을 읽을 필요는 없습니다.

CURRENT.md에는 짧은 현재 목표, 상태, 다음 행동과 링크를 둡니다. 재사용할 현재 사실은 주제별 지식 문서에, 의미 있는 진척의 상세 근거는 날짜별 작업 일지에 둡니다. 새 AAPB 일지는 `worklogs/YYYY-MM/`을 사용합니다. 기존 위치를 보존하고 요청받았거나 필요한 기록만 만드세요. 구성원 저장소의 로컬 기록은 별도로 유지하고, 적용되는 등록 저장소를 명시하며 로컬 전용·관리 주체 규칙을 따릅니다. 기록 작성에는 Git 저장소가 필요하지 않습니다.

허용된 산출물 안에서 정확한 근거 위치, 수치, 단위, 명령과 URL을 보존합니다. 실행한 검사, 확인한 내용과 남은 미확인 사항을 밝히세요. 재사용한 검증에는 관련 입력과 조건이 그대로임을 명시하고 필수 검사 규칙을 따라야 합니다. 보고서를 줄이더라도 이러한 구분을 없애지 않습니다.

## 초안 검토

메인 작업에서 산출물을 직접 작성할 수 있습니다. 길고 독립적인 초안을 선택적으로 위임할 때는 선택한 형식, 저장 위치, 범위를 정한 사실, 근거 위치, 짧은 관련 이력, 제약과 미확인 사항을 전달합니다. 사용자 모델·추론 강도 선택과 명시적 역할 설정을 보존하고 호스트에서 지원하는 기능만 사용하세요. 공통 현재 상태나 채택한 지식을 직접 교체하게 하지 말고 별도 DRAFT를 요청합니다.

메인은 반영 전에 초안의 경로와 소스 범위, 수치, 명령, URL, 결정과 미검증 상태를 원래 근거와 대조합니다. 해결하지 못한 미확인 사항은 그대로 남깁니다. 역할 프롬프트는 파일 권한을 강제하지 않습니다. 검토하지 않은 초안은 채택한 명세나 검증된 사실이 아닙니다.

커밋·PR 형식은 설정된 프로젝트·호스트 정책을 따르며 중복 승인 절차를 추가하지 않습니다. 이미 승인된 로컬 이정표는 진행하고 원격 게시는 별도 범위로 둡니다.
