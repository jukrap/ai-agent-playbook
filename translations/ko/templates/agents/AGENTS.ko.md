# 프로젝트 지침

## 작업 범위와 근거

- 허용된 범위에서 현재 요청에 필요한 조사, 구현, 검증과 검토까지 완료한다. 무관한 변경과 명시적 승인 조건을 보존한다. 목표를 크게 바꾸는 결정은 일찍 질문하고, 다음 행동의 승인을 요청하기 전에 이미 허용된 준비를 마친다.
- 코드·설정·명령 결과로 현재 동작을 확인한다. 채택한 명세와 결정으로 의도한 동작을 확인하고, 중요한 불일치는 알린다.
- 도구를 고르기 전에 이 저장소에서 사용하는 패키지 관리자, 실행 환경, 빌드 명령과 관련 파일의 역할을 확인한다.
- 코드나 Git 작업 전에 선택한 저장소와 적용 지침을 확인한다. Git이 있으면 루트, 브랜치와 미반영 변경도 확인하고 사용자 편집과 기존 worktree를 보존한다. 기록은 Git 없이 사용할 수 있으므로 기록을 남기기 위해 Git을 초기화하지 않는다.
- AAPB 다중 저장소 작업 공간의 공통 기록은 명시적으로 등록된 구성원에만 연결된다. 코드 작업 전에 현재 구성원을 확인하거나 등록된 저장소를 선택한다. 작업 공간 루트에서 대상이 불명확하면 먼저 확인한다. 발견한 후보, 형제 폴더와 링크는 등록이나 여러 저장소의 일괄 Git 작업 허가를 뜻하지 않는다.
- 관련 경로, 심볼과 필터로 좁힌 기록부터 살핀다. 근거가 부족하거나 영향을 받는 의존 관계를 확인해야 할 때 탐색을 넓힌다. 독립적인 읽기는 묶고 잘린 출력은 빠진 부분을 다시 읽는다.

## 아키텍처와 변경

- 프로젝트에서 채택한 모듈 경계와 공개 계약을 따른다. 프레임워크 이름만으로 아키텍처를 정하지 않는다.
- 아키텍처 문서가 없으면 현재 구조와 의존성을 먼저 살핀다. 새 작업에서는 허용된 범위 안에서 규모에 맞는 구조를 고르고, 이후 작업이 지켜야 할 결정을 기록한다.
- 경계를 바꾸기 전에 호출부, 데이터 관리 주체, 호환성, 검증 방법을 확인한다. 임시 예외와 그 예외를 없앨 조건을 명시한다.
- 아키텍처의 상세 내용은 프로젝트의 기존 명세나 결정 문서에 둔다. 문서가 실제로 존재할 때 이 지침에서 연결하고, 설계 전체를 루트 지침에 반복하지 않는다.
- CURRENT.md 같은 기존 기록 진입점에서 현재 목표, 근거와 다음 할 일을 찾는다. 모든 과거 기록 대신 관련 링크만 읽는다.

## 기록과 협업

- 의미 있는 단계 완료, 결정, 중요한 사실 확인, 차단과 인계를 기존 프로젝트 기록에 남긴다. 일상적인 편집이나 매 응답마다 새 일지를 만들 필요는 없다.
- CURRENT.md는 짧고 다음 행동이 분명하도록 유지한다. 현재 유효한 규칙, 용어와 계약은 주제별 지식 문서에 두고 적용 저장소, 출처, 확인 날짜와 확정·가정 상태를 표시한다. 배경, 판단 근거, 변경, 정확한 검증 결과와 남은 일은 날짜별 상세 작업 일지에 남긴다. 프로젝트가 새 구조를 사용한다면 새 일지는 월별 폴더에 둔다.
- 기존 기록, 로컬 전용 규칙과 관리 주체를 보존한다. 구성원 저장소의 기존 로컬 기록은 별도 출처로 연결한다. 자동으로 옮기거나 과거 주장을 현재 사실로 승격하지 않는다. 전역 참고 자료는 작업에 필요할 때 고르는 자료이며 필수 읽기 순서가 아니다.
- 독립적인 작업 담당자에게 명확한 담당 범위와 근거를 전달한다. 공통 현재 상태 문서는 담당자를 하나씩 정하고, 병렬 기록 작업은 별도 초안 파일을 사용한다. DRAFT의 출처 경로, 수치, 명령, URL, 결정과 미확인 사항을 검토한 뒤 반영한다. 역할 지침은 파일 시스템 경계를 강제하지 않는다.

## 검증과 전달

- 프로젝트 필수 검사와 변경된 동작에 맞는 검증을 실행한다. 정적 검사, 준비된 입력을 사용한 검사, 실제 앱·기기 실행을 구분한다.
- 관련 입력과 실행 조건이 같고 필수 검사 규칙이 허용할 때만 통과한 결과를 재사용한다. 새 변경, 실패나 미해결 우려가 있으면 검증을 반복하거나 넓힌다. 실행 가능한 예제와 설정 계약을 바꾸었다면 여전히 그에 맞는 검사가 필요하다.
- 정확한 명령, 결과와 남은 한계를 프로젝트의 근거 보관 위치에 남긴다. 오래된 현재 상태는 갱신하되 과거 기록을 현재 사실로 바꾸지 않는다.
- 사용자가 허용한 범위에서 프로젝트의 Git·게시 규칙을 따른다. 스테이징 내용을 확인하고 로컬 전용·민감 자료를 공개 산출물에서 제외한다.
