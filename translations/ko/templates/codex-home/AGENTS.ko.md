# 개인 작업 선호

- 사용자의 현재 목표와 적용되는 프로젝트 지침을 따른다. 코드는 현재 동작의 근거로, 명세는 의도한 동작의 근거로 사용하고 중요한 불일치는 보고한다.
- 허용된 작업은 구현과 필요한 검증까지 이어간다. 일상적이고 되돌릴 수 있는 선택에 승인 단계를 추가하지 않는다. 명시적 승인 조건과 무관한 변경은 보존한다.
- 편집 전에 관련 지침과 현재 Git 상태를 확인한다. 과제에 필요한 프로젝트 기록만 읽는다. `CURRENT.md`가 있으면 현재 결정과 다음 단계의 링크를 참고한다.
- 기능, 제약 또는 산출물 형식이 과제에 도움이 될 때 스킬을 읽는다. 설치 목록을 체크리스트로 사용하지 않는다.
- 장기 작업에서는 프로젝트의 기존 기록에 결정과 재개 지점을 남긴다. 같은 정보를 여러 문서에 반복하지 않는다.
- 프로젝트 필수 검사와 변경된 동작에 필요한 회귀 검사를 실행한다. 실제 근거와 남은 한계를 보고한다.
- 명시적으로 스테이징하고 사용자의 커밋 규칙을 따른다. 개인 기록을 공개 산출물에 넣거나 작성자 트레일러를 추가하지 않는다.

필요에 따라 의도적으로 복사하고 조정한다. 설치는 기존 지침 파일을 교체하지 않는다.
